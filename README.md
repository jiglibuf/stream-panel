# Пульт стрима

Планшет на держателе вместо цифрового блока: сцены, эфир, запись, повтор, звук — и всё это с телефона/планшета
в домашней сети или в tailnet.

Состав: Python-сервис (aiohttp, порт 8090) — единственный, кто говорит с OBS через obs-websocket v5;
фронт (React + Vite, PWA) отдаётся тем же сервисом.

Статус: в разработке, v1 (сцены + транспорт). Звуковая панель — следующая итерация.

## Требования

- OBS Studio с включённым obs-websocket v5 (`Инструменты → Настройки WebSocket-сервера`, порт 4455).
- Python 3.12+ (для сервиса), Node 20+ (только для сборки фронта).
- Запущенный OBS — источник правды по состоянию; без него пульт показывает «OBS офлайн».
- Tailscale на компьютере со стримом и на планшете (для доступа по HTTPS и установки на домашний экран).

## Сборка

Фронт собирается один раз (и после каждого изменения):

```bash
npm --prefix frontend run build
```

Сервис раздаёт готовые файлы из `frontend/dist`. Если сборки нет — отдаётся страница-заглушка
«фронт ещё не собран».

## Как поднять

```bash
scripts/run.sh
```

Скрипт поднимает сервис в фоне, пишет журнал в `panel.log` и PID в `run/panel.pid`.
На экран выводится адрес. Запуск идемпотентен: повторный `scripts/run.sh` при живом процессе просто
скажет, что всё уже работает, а если порт 8090 занят посторонним процессом — откажется стартовать.

Первое окружение (`.venv`) создаётся скриптом `scripts/test.sh`.

## Как остановить

```bash
scripts/stop.sh
# или то же самое:
scripts/run.sh --stop
```

Останов идемпотентен: если сервис не запущен, скрипт просто сообщит об этом. Сначала посылается
`SIGTERM`, при отказе завершиться — `SIGKILL`; чужие процессы не затрагиваются.

## Автозапуск после перезагрузки

`scripts/run.sh` живёт, пока машина не перезагрузится. Чтобы пульт поднимался сам (и возвращался
при падении), он ставится службой пользователя:

```bash
mkdir -p ~/.config/systemd/user
cp deploy/stream-panel.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now stream-panel
sudo loginctl enable-linger "$USER"   # старт даже без входа в систему
```

Проверка, журнал и отключение обратно на ручной запуск:

```bash
systemctl --user status stream-panel
journalctl --user -u stream-panel -n 20
systemctl --user disable --now stream-panel
```

Служба и `scripts/run.sh` делают одно и то же — держать оба сразу не нужно, порт 8090 один.
Если после ребута на планшете `502` — значит служба не поднялась: смотреть
`systemctl --user status stream-panel`.

## Токен доступа

Сервис пускает только клиентов из приватных сетей и tailnet и требует токен. Токен —
в файле `config.json` рядом с репозиторием на компьютере со стримом; он создаётся сам при первом
запуске (права `0600`, в git не попадает). Показывать его никому не нужно — достаточно один раз
ввести на планшете.

На экране пульта первый визит открывает поле ввода. Введите токен из `config.json` — он сохранится
в браузере планшета и больше спрашиваться не будет. Если сервер ответит `401` (токен сменили или
стёрли `config.json`), сохранённый токен сбрасывается и поле ввода появляется снова — введите новый.
Токен не лежит ни в HTML страницы, ни в её адресе.

## Установка на домашний экран планшета

PWA ставится только по HTTPS: через `http://192.168.3.153:8090` браузер установку не предложит,
поэтому используйте tailnet-адрес.

1. На компьютере со стримом включите раздачу (см. следующий раздел) и запустите сервис.
2. На планшете откройте `https://beelink-fedora.tailba048e.ts.net:10444`.
3. Введите токен, убедитесь, что состояние OBS пришло.
4. Меню браузера → «Установить приложение» (Chrome/Android) или «На экран “Домой”» (Safari/iOS).
5. Запускайте пульт с иконки на домашнем экране — он откроется в полноэкранном режиме
   без адресной строки.

## Раздача в tailnet (HTTPS)

Пульт публикуется только внутри tailnet — **без Funnel**, наружу он выставляться не должен.
На компьютере со стримом:

```bash
tailscale serve --bg --https=10444 http://127.0.0.1:8090
```

Адрес: `https://beelink-fedora.tailba048e.ts.net:10444`. Порт `10444` выбран потому, что
`443`, `8443` и `10443` на узле заняты другой раздачей. Проверить, что наружу ничего не уходит,
можно так — в выводе у порта должно стоять `(tailnet only)`, а не `(Funnel on)`:

```bash
tailscale serve status
```

Выключить раздачу: `tailscale serve --https=10444 off`.

## Резервный доступ по LAN

Сервис слушает `0.0.0.0:8090`, поэтому в домашней сети пульт доступен напрямую:

```
http://192.168.3.153:8090
```

Это резервный путь: по нему пульт работает, но установить приложение на домашний экран нельзя
(для PWA нужен HTTPS). Токен вводится так же.

## Что умеет пульт

- **Сцены** — переключение текущей сцены.
- **Эфир** — старт и стоп трансляции (со стороны планшета кнопка требует подтверждения).
- **Запись** — одна кнопка-переключатель; сторону (старт/стоп) решает OBS.
- **Повтор** — сохранение повтора (если буфер повтора включён в OBS).
- **Звук** — mute и громкость отдельно для микрофона и системного звука, плюс живые уровни.
- **Паника** — мгновенно переключает на чёрный экран и глушит микрофон; работает даже при
  потере связи с OBS, не дожидаясь подтверждений.

Состояние с OBS синхронизируется само; при обрыве связи кнопки становятся недоступны, а
разрушительные действия (старт/стоп эфира, запись, повтор) сервис отклонит, пока состояние не
подтвердится заново.

## Автозапуск (опция)

Чтобы сервис поднимался при загрузке компьютера, есть unit пользователя systemd:
`deploy/stream-panel.service`. Установка и управление — в `deploy/README.md`. Не включайте его
одновременно с `scripts/run.sh` — они используют один и тот же порт.

## Тесты

```bash
# быстрые, без OBS
scripts/test.sh

# против живого OBS (меняют состояние; короткий тестовый эфир разрешён)
scripts/test.sh --live

# фронт
npm --prefix frontend test
```
