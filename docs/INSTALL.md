# Установка

Две дороги: **(A) только пульт стрима** и **(B) пульт + RedZone**. Дороги независимы — B включает в
себя A, но добавляет модуль RedZone, хаб MediaMTX и раздельный звук. Идите по шагам сверху вниз; после
каждого шага есть команда проверки и то, что должно быть в ответе.

Нигде не требуются root-права: и сервис, и хаб, и звук настраиваются в пользовательской сессии.
Все рабочие секреты живут в `~/.config/stream-panel/` и в `config.json` рядом с проектом — вне git.

## Чего требует система

- **OBS Studio** с включённым obs-websocket v5 — сервер OBS. Без него пульт покажет «OBS офлайн».
- **Python 3.12+** — для сервиса пульта. Зависимости (aiohttp, websockets) ставятся в `.venv` рядом с
  проектом; системный Python не трогается.
- **Node 20+** — только чтобы собрать фронт один раз (и после правок фронта). В бою Node не нужен.
- **Tailscale** — чтобы открыть планшету пульт по HTTPS (нужно для установки на домашний экран и
  Wake Lock). По обычному `http://<IP>` пульт тоже работает, но установить приложение нельзя.
- Для дороги B дополнительно: **Docker** (хаб MediaMTX) и **PipeWire** с `pactl`/`pw-dump`/`pw-link`
  (раздельный звук).

# Дорога A: только пульт стрима

## A1. Включите obs-websocket v5 в OBS

`Инструменты → Настройки WebSocket-сервера → Включить WebSocket-сервер`, порт оставьте `4455`, задайте
пароль и нажмите «Применить». Пароль хранится OBS в файле
`~/.config/obs-studio/plugin_config/obs-websocket/config.json`; пульт читает его оттуда и берёт пароль
сам — вводить его в пульт не нужно.

**Проверка:**

```bash
python3 -c "import json,pathlib;p=pathlib.Path.home()/'.config/obs-studio/plugin_config/obs-websocket/config.json';c=json.loads(p.read_text());print('enabled:',c.get('server_enabled'),'port:',c.get('server_port'))"
```

В ответе должно быть `enabled: True port: 4455`. `enabled: False` — сервер OBS выключен, включите его в
настройках и повторите.

## A2. Поставьте зависимости и юниты

```bash
tools/install.sh
```

Скрипт создаёт `.venv` и ставит Python-зависимости, собирает фронт, если он ещё не собран, создаёт
каталог конфига `~/.config/stream-panel/` с шаблоном окружения `env.example`, копирует юниты из
`deploy/systemd/` в `~/.config/systemd/user/` и делает `systemctl --user daemon-reload`. Юниты при этом
**не включаются** в автозапуск: стрим-стек должен подниматься тогда, когда вы стримите. Скрипт
идемпотентен — повторный запуск ничего не дублирует и не перезаписывает рабочие файлы с токенами.
Флаги: `--with-frontend` (пересобрать фронт), `--skip-frontend`, `--enable` (сразу включить автозапуск).

**Проверка:**

```bash
.venv/bin/python -c "import aiohttp, websockets; print('ok')"
```

Ожидается `ok`.

## A3. Соберите фронт

Если `tools/install.sh` уже собрал фронт, шаг можно пропустить. Иначе:

```bash
npm --prefix frontend run build
```

Сервис раздаёт готовые файлы из `frontend/dist`. Если сборки нет — вместо пульта отдаётся
страница-заглушка «фронт ещё не собран».

**Проверка:**

```bash
test -f frontend/dist/index.html && echo "сборка на месте"
```

Ожидается `сборка на месте`.

## A4. Поднимите сервис

```bash
tools/panel.sh up
```

(Внутри — `scripts/run.sh`: сервис запускается в фоне, журнал пишется в `panel.log`, PID — в
`run/panel.pid`.) Запуск идемпотентен: повторный `up` при живом процессе сообщит, что всё работает, а
если порт 8090 занят чужим процессом — откажется стартовать и покажет, кто его держит.

**Проверка:**

```bash
tools/panel.sh status
curl -sS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8090/
```

`status` печатает запущенный PID, а `curl` — `200` (страница пульта отдаётся без токена).

## A5. Возьмите токен доступа

Сервис пускает только клиентов из приватных сетей и tailnet и требует токен. Токен хранится в
`config.json` рядом с проектом (права `0600`, в git не попадает). `tools/install.sh` создаёт файл из
шаблона `config.example.json`; **заглушку в токене замените своим значением**:

```bash
openssl rand -hex 21     # впишите результат в поле "token" файла config.json
```

Если удалить `config.json`, сервис создаст токен сам при первом запуске — тогда достаточно прочитать
его из файла. Показывать токен никому не нужно: он вводится один раз на планшете и сохраняется в
браузере.

**Проверка:**

```bash
.venv/bin/python -c "import json;print('токен задан:', len(json.load(open('config.json'))['token']) >= 16)"
curl -sS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8090/api/state
```

Первое — `токен задан: True`; второе — `401` (без токена доступа нет, это норма).

## A6. Откройте пульт в tailnet (HTTPS)

Пульт публикуется **только внутри tailnet, без Funnel** — наружу он выставляться не должен.

```bash
tailscale serve --bg --https=10444 http://127.0.0.1:8090
```

Адрес будет вида `https://<адрес-хоста-стрима>.ts.net:10444`. Порт `10444` выбран потому, что `443`,
`8443` и `10443` на узле часто заняты другой раздачей; возьмите свободный, если он занят и у вас.

**Проверка:**

```bash
tailscale serve status
```

В выводе у порта должно стоять `(tailnet only)`, а не `(Funnel on)`. Выключить раздачу:
`tailscale serve --https=10444 off`.

## A7. Установите на домашний экран планшета

1. На планшете откройте `https://<адрес-хоста-стрима>.ts.net:10444`.
2. Введите токен из `config.json` и убедитесь, что пришло состояние OBS.
3. Меню браузера → «Установить приложение» (Chrome/Android) или «На экран “Домой”» (Safari/iOS).
4. Запускайте с иконки — пульт откроется в полноэкранном режиме без адресной строки.

## A8. Автозапуск (по желанию)

Чтобы пульт поднимался сам и возвращался при падении:

```bash
tools/install.sh --enable
loginctl enable-linger "$USER"          # старт даже без входа в систему
```

`--enable` включает юниты, уже скопированные установщиком. Включить руками только один сервис можно
так: `systemctl --user enable --now stream-panel.service`.

**Проверка:**

```bash
systemctl --user status stream-panel.service
```

Состояние — `active (running)`. Если после перезагрузки планшет показывает `502`, служба не поднялась
— смотрите `systemctl --user status` и `journalctl --user -u stream-panel.service -f`.

Юнит и `tools/panel.sh up` делают одно и то же — держать оба сразу не нужно, порт 8090 один.

# Дорога B: пульт + RedZone

Пройдите дорогу A целиком, затем добавьте модуль и сервисы ниже.

## B1. Убедитесь, что модуль RedZone на месте

RedZone — модуль пульта: он лежит в `modules/redzone/` и запускается как `python3 -m modules.redzone`.
Отдельного «включения в конфиге» нет: если каталог модуля на месте, его службы работают; если модуля
нет — службы из `deploy/systemd/` сами пропускаются (у них стоит `ConditionPathExists`). Свои
настройки модуль читает из `~/.config/stream-panel/redzone.json` и переменных окружения.

**Проверка:**

```bash
python3 -m modules.redzone --help
```

Скрипт печатает список подкоманд модуля (сборка раскладки, чат, сетка, каст, звук). Точные команды —
в `modules/redzone/README.md`.

## B2. Соберите раскладку сцен RedZone

Раскладку собирает сборщик модуля (подкоманда из `--help`; см. `modules/redzone/README.md`). Скрипт
идемпотентен: повторный запуск ничего не дублирует. Перед правкой коллекции делается копия файла сцен в
`modules/redzone/backup/`.

> Сборщик **отказывается работать при активном эфире или записи** — это защита от порчи кадра.

**Проверка:** после сборки в OBS появились сцены RedZone (мозаика и карты во весь кадр), а обычные
сцены не тронуты. Переключение фокуса — сценой из пульта или хоткеями `Ctrl+Num…`.

## B3. Поднимите хаб MediaMTX

Скопируйте пример конфига и впишите свои ключи (каждую заглушку `<...>` замените своим случайным
значением):

```bash
cp deploy/mediamtx/mediamtx.example.yml deploy/mediamtx/mediamtx.yml
cd deploy/mediamtx && docker compose up -d
```

Хаб занимает порты: `8554` RTSP, `1935` RTMP, `8888` HLS, `8889` WebRTC, `8890` SRT, `9997` API.
Пути: `program` (то, что уходит в эфир) и `card1..cardN` (карты друзей). Подробности — в
[`COCAST.md`](COCAST.md).

**Проверка:**

```bash
curl -s http://127.0.0.1:9997/v3/paths/list | head -c 120
docker logs --tail=5 mediamtx
```

API отвечает JSON, в логе нет `configuration file not found`. Если файл конфига «не находится» при
том, что он есть, проверьте флаг `,z` у монтирования — на Fedora это SELinux.

## B4. Настройте звук

Откройте в пульте вкладку «Звук», выберите устройство вывода (наушники), затем режим **«Стрим»**. Режим
поднимает три виртуальных выхода (`rz_mix`, `game_mix`, `discord_mix`), заводит их петлями в
устройство, делает `rz_mix` выходом по умолчанию и включает сторож.

**Проверка:**

```bash
pactl get-default-sink                                   # ожидается: rz_mix
pactl list short modules | grep -c module-loopback       # ожидается: 3
systemctl --user is-active rz-mix.service                # ожидается: active
```

Полное устройство звука и грабли — в [`AUDIO.md`](AUDIO.md).

## B5. Включите службы модуля

`tools/install.sh` уже скопировал юниты в `~/.config/systemd/user/`. Включаются они по отдельности —
только те, что нужны.

**Локальный чат-релей** (по желанию): читает чат канала и отдаёт страницу для браузерного источника
OBS на `127.0.0.1:8097`. Канал задаётся переменной `CHAT_CHANNEL` в `~/.config/stream-panel/env`
(шаблон — `env.example`), свой, не чужой.

```bash
systemctl --user enable --now rz-chat.service
curl -s http://127.0.0.1:8097/health
```

`/health` показывает состояние соединения и «сколько секунд назад было последнее сообщение» — это
различает «не подключено» и «подключено, но тихо».

**Турнирная сетка** (по желанию): снимок страницы турнира кладётся картинкой в источник OBS и
обновляется таймером раз в 5 минут. Адрес страницы — `BRACKET_URL` в том же `env`.

```bash
systemctl --user enable --now rz-bracket.timer
systemctl --user list-timers rz-bracket.timer    # ожидается: следующий запуск через ~5 минут
```

**Совместный каст** (по желанию): релей раздаёт соведущим готовый эфир из хаба. Его можно держать
включённым постоянно — он молчит, пока нет ни адреса Twitch, ни потока в хабе.

```bash
systemctl --user enable rz-cocast-relay.service
```

Переключение эфира на хаб делается вручную (прерывает эфир на несколько секунд); порядок действий и
грабли — в [`COCAST.md`](COCAST.md), гайд для самих друзей — в [`COCAST-FRIENDS.md`](COCAST-FRIENDS.md).

## B6. Режим игры

`tools/game-mode.sh on` гасит стрим-стек (сервисы, хаб, аналитику) и возвращает машину в игровое
состояние, освобождая VRAM; `tools/game-mode.sh off` возвращает как было.

**Проверка:** `tools/game-mode.sh status` показывает текущее состояние стрим-стека.

# Справочные разделы

## OBS (obs-websocket v5)

- Пульт — **единственный**, кто держит постоянное соединение с OBS ради команд и состояния. Модуль
  RedZone и сервис аналитики живут отдельно; модуль открывает короткое соединение только на время
  разовых операций (сборка раскладки и подобное), поэтому пульт работает и без него.
- Адрес сервера OBS — `127.0.0.1:4455`, пароль — из
  `~/.config/obs-studio/plugin_config/obs-websocket/config.json`. Путь можно переопределить переменной
  окружения `OBS_WS_CONFIG`.
- Коллекция сцен лежит в `~/.config/obs-studio/basic/scenes/*.json`. OBS пишет файл при выходе, поэтому
  скрипты модуля перед правкой копируют его в `backup/` и отказываются работать в эфире/записи.
- Источники «Звук системы» и «Дискорд» должны входить в активную сцену, иначе звук не попадёт в микс:
  сам по себе источник, которого нет в текущей сцене, не микшируется.

## Звук

Полностью — в [`AUDIO.md`](AUDIO.md). Коротко: три виртуальных микса (`game_mix` — игра,
`discord_mix` — голосовой чат, `rz_mix` — всё вместе и выход по умолчанию), петли заводят их в
наушники, а OBS захватывает мониторы `game_mix` и `discord_mix` отдельными дорожками. Служба-сторож
держит связи петель после переподключения наушников. Заготовки для PipeWire — в `deploy/pipewire/`.

## Хаб MediaMTX

Конфиг — `deploy/mediamtx/`. Порты и пути — в [`COCAST.md`](COCAST.md). Ключи публикации выдаются
друзьям лично, в репозитории их нет: в `mediamtx.example.yml` только заглушки, а рабочий
`mediamtx.yml` в git не попадает.

## Модуль аналитики (необязательно)

Аналитика — **отдельный проект** со своим репозиторием; в этот репозиторий она не входит. Её юнит
(`deploy/systemd/dota-analytics.service`) пропускается, если проекта рядом нет. Она принимает Game
State Integration от Dota 2 на порт `53000`, хранит историю в SQLite и отдаёт оверлеи (тикер, тепловая
карта) на локальные страницы, которые подключаются браузерным источником в OBS. Без неё оверлеи честно
показывают «сервис недоступен», а пульт и RedZone работают как обычно. Как связать аналитику с
RedZone — в [`MODULES.md`](MODULES.md).
