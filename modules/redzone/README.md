# Модуль RedZone

Мультитрансляция нескольких карт Dota 2 в OBS: раскладка «одна большая карта + полоса
миниатюр + правая колонка», локальный чат-релей, турнирная сетка, совместный каст через
хаб MediaMTX и разделение звука игры и голосового чата.

RedZone — **не отдельная программа, а модуль пульта**. Всё запускается одной точкой входа
из корня репозитория:

```bash
python3 -m modules.redzone status
python3 -m modules.redzone --help
```

Модуль говорит с OBS напрямую по obs-websocket v5 (как и ядро пульта) и самодостаточен:
его можно поднять и без сервиса пульта.

## Что умеет

| Часть | Что делает |
|-------|------------|
| Раскладка | собирает сцены RedZone: источники карт, рамки фокуса, подписи, нижнюю полосу, правую колонку. Идемпотентно — повторный запуск ничего не дублирует |
| Чат | читает чат Twitch по IRC (только чтение) и отдаёт страницу с прозрачным фоном по localhost — встроенный браузер OBS не грузит внешние сайты, а локальную страницу рисует |
| Сетка | снимает страницу турнира внешним браузером и кладёт PNG картинкой в сцены (у модуля турнира тема тёмная, страница турнира часто отдаёт 403) |
| Совместный каст | OBS отдаёт микс в хаб, релей копирует поток в Twitch без перекодирования, соведущие смотрят из хаба с задержкой меньше секунды |
| Звук | разводит игру и голосовой чат на два виртуальных выхода (микса), петлями возвращает их в наушники, держит сторож и проверяет, что звук доходит и до ушей, и до эфира |

## Требования

- OBS Studio с включённым obs-websocket v5 (порт 4455).
- Python 3.12+ и пакет `websockets` (для разговора с OBS). Файлы в `scripts/`, которым
  нужен только `pactl`/`systemctl`/`ffmpeg`, идут на системном питоне.
- `ffmpeg`, `pactl` (PipeWire), `systemctl --user`.
- Внешний браузер для снимка сетки (`google-chrome` по умолчанию).
- Docker с хабом MediaMTX — только для совместного каста.

## Установка

1. Скопируйте образец конфига и впишите свои значения:

   ```bash
   mkdir -p ~/.config/stream-panel
   cp modules/redzone/config.example.json ~/.config/stream-panel/redzone.json
   ```

   Порознь ключи и адреса можно не хранить в файле, а задавать переменными окружения
   `REDZONE_*` (см. раздел «Конфиг»).

2. Проверьте, что пути подобрались верно:

   ```bash
   python3 -m modules.redzone config
   ```

3. Соберите раскладку (OBS должен быть запущен, эфира быть не должно):

   ```bash
   python3 -m modules.redzone build
   ```

4. Хоткеи и порядок сцен в файле коллекции (нужна вторая, «пустая» коллекция для
   переключения — имя задаётся в конфиге):

   ```bash
   python3 -m modules.redzone collection --dry-run   # посмотреть
   python3 -m modules.redzone collection             # применить
   ```

5. Игровой Lua-скрипт фокуса (звучит только крупная карта): положите
   `modules/redzone/lua/rz_audio_focus.lua` туда, откуда OBS берёт скрипты, и включите его
   в «Инструменты → Скрипты». Микрофон скрипт не трогает.

6. Службы-сторожа (необязательно, но с ними модуль переживает перезагрузку). Примеры
   юнитов пользователя — в `deploy/systemd/`. Имя файла в репозитории должно совпадать с
   именем источника картинки: положите юниты в `~/.config/systemd/user/`, поправьте в них
   путь к питону/скриптам и включите:

   ```bash
   systemctl --user daemon-reload
   systemctl --user enable --now rz-mix.service      # сторож звука
   systemctl --user enable --now rz-chat.service     # чат-релей
   systemctl --user enable --now rz-bracket.timer    # обновление сетки
   ```

   Сторож звука требует `XDG_RUNTIME_DIR` и `PULSE_SERVER` в юните, иначе `pactl` не находит
   PipeWire.

## Подкоманды

```bash
# Жизненный цикл
python3 -m modules.redzone up [--build]   # чат + звук + таймер сетки; --build ещё и раскладку
python3 -m modules.redzone down           # погасить и вернуть звук как было
python3 -m modules.redzone status         # что поднято, куда смотреть

# Раскладка
python3 -m modules.redzone build [--hide] [--styles]
python3 -m modules.redzone column                     # правая колонка: сетка + чат
python3 -m modules.redzone point-cards show|hub|tiles|url [--cards 2 3] [--url …]
python3 -m modules.redzone collection [--dry-run]

# Чат, сетка, каст
python3 -m modules.redzone chat [--status] [--test ТЕКСТ]
python3 -m modules.redzone bracket [--place]
python3 -m modules.redzone cocast on|off|status|testfeed|selftest|viewer-key [--yes]

# Звук
python3 -m modules.redzone audio enable|disable|watch|check|levels
python3 -m modules.redzone audio route [--probe] | phones [--device ИМЯ]
python3 -m modules.redzone audio rescue | watch-mic [--seconds 40]
python3 -m modules.redzone audio dota-fix [--watch]
python3 -m modules.redzone audio split | fix-scenes | scene-report | device [--name ИМЯ]
python3 -m modules.redzone audio-check [--probe]
```

Подкоманды, которые говорят с OBS (`build`, `column`, `bracket`, `collection`,
`point-cards`, часть `audio`) **отказываются работать при идущем эфире или записи** —
правка сцен в этот момент недопустима.

`cocast on|off` прерывают эфир на несколько секунд (OBS перезапускает публикацию), поэтому
при активном эфире нужен явный `--yes`.

## Конфиг

Основной файл: `~/.config/stream-panel/redzone.json`. Другой путь — ключом
`--config ПУТЬ` или переменной `REDZONE_CONFIG`. Порядок разрешения значений:
значения по умолчанию → файл → переменные окружения `REDZONE_*`.

Полный образец со всеми ключами и плейсхолдерами — `config.example.json`. Ключи, которые
отвечают за конкретную машину (адреса, имена коллекций, ключи хаба), в коде не зашиты.

Основные переменные окружения (перекрывают файл): `REDZONE_CONFIG`,
`REDZONE_STATE_DIR`, `REDZONE_OBS_HOST`, `REDZONE_OBS_PORT`, `REDZONE_OBS_WS_CONFIG`,
`REDZONE_SCENES_DIR`, `REDZONE_OBS_COLLECTION`, `REDZONE_CHAT_CHANNEL`,
`REDZONE_CHAT_PORT`, `REDZONE_BRACKET_URL`, `REDZONE_HUB_API`, `REDZONE_HUB_RTSP`,
`REDZONE_HUB_RTMP`, `REDZONE_HUB_CONFIG`, `REDZONE_STREAM_HOST` (внешний адрес хаба для
проверки доступа), `REDZONE_AUDIO_*` и `REDZONE_COCAST_*`.

**Секреты.** Ключи карт и ключ зрителя объявляются в конфиге хаба (`deploy/mediamtx/`),
а не в этом модуле. Ключ Twitch модуль не хранит и не печатает: `cocast on` сохраняет адрес
и ключ из настроек OBS в файл с правами 600 (путь — `cocast.target`) и оттуда возвращает их
обратно. Релей читает тот же файл.

## Структура

```
modules/redzone/
├── redzone.py        точка входа и подкоманды
├── config.py         конфиг: умолчания, файл, переменные окружения
├── obsclient.py      синхронный клиент obs-websocket v5
├── layout.py         раскладка сцены: источники, сцены, трансформы
├── column.py         правая колонка: чат под высоту колонки
├── bracket.py        снимок турнирной сетки и его место в сценах
├── collection.py     хоткеи и порядок сцен в файле коллекции
├── chat.py           чат-релей (IRC Twitch → localhost, SSE)
├── cocast.py         совместный каст через хаб
├── audio.py          звук: режимы, сторож, проверки, развод источников
├── status.py         состояние модуля
├── scripts/          низкоуровневая часть: pactl/systemd/ffmpeg (запускает модуль)
├── lua/              игровой Lua-скрипт фокуса для OBS
├── tiles/            страницы-заглушки карт
└── overlay/          заготовка картинки сетки
```

Файлы в `scripts/` — внутренняя часть модуля; вручную их запускать не нужно, все действия
делаются подкомандами. Часть проверок вынесена в `modules/redzone/scripts/`.

## Грабли (всё проверено на живой машине)

**OBS и раскладка**

- Встроенный браузер OBS **не грузит внешние сайты**: виджеты чата и встраиваемые страницы
  показывают пустоту, а локальные страницы рисуются. Поэтому чат отдаёт свой релей, а сетку
  показывает картинкой.
- OBS **выбрасывает источники, на которые не ссылается ни одна сцена**, при первом же
  сохранении коллекции. Сборщик сначала создаёт источники и сцены, и только потом убирает
  лишнее.
- `SetSceneItemTransform` принимает **плоские поля** (`positionX`, `boundsWidth`, …).
  Вложенная форма молча игнорируется: запрос отвечает успехом, положение не меняется.
- `boundsWidth`/`boundsHeight` **меньше 1 отклоняют весь запрос** — позиция тоже не
  применяется, элемент падает в (0,0). Нулевые bounds не отправляем.
- Порядок элементов растёт вверх: индекс 0 — самый нижний. Рамку карты ставим ниже самого
  видео.
- `color_source` ждёт цвет в формате **0xAABBGGRR** (ABGR), а не ARGB.
- `vkcapture-source` выбирает окно **по имени процесса**; два клиента одной игры
  неразличимы — раздельный захват нескольких копий остаётся открытой задачей.
- Правка файла коллекции без перезапуска OBS: переключить коллекцию (OBS сохранит текущую
  на диск), поправить JSON, вернуть коллекцию. Переключение коллекции может уронить
  obs-websocket — тогда лечится только перезапуском OBS.
- Хоткеи OBS хранит с **плоскими модификаторами** (`{"key": …, "control": true}`);
  вложенный `"modifiers"` молча теряется. Хоткеи сцен — в файле коллекции, а не в коллекции.

**Хаб MediaMTX и совместный каст**

- `pathDefaults.overridePublisher` по умолчанию `true`: второй публикатор выбивает первого.
  Для общего эфира ставить `false`, иначе тестовая картинка может подменить эфир.
- Права привязываются к пути: у каждого гостя свой ключ ровно на его карту, у зрителя —
  только `read` на путь общего эфира. Проверять доступ надо **с нелокального адреса**:
  правило для `127.0.0.1` пускает локальные подключения без пароля.
- Читать из хаба только **RTSP** — SRT-чтение падает.
- Правку `mediamtx.yml` не подхватывает `docker compose up -d` у работающего контейнера:
  нужен перезапуск. `kill -s HUP` контейнер останавливает.
- На Fedora системный `ffmpeg` может быть собран без нативного декодера H.264, и медиа-
  источники OBS не смогут декодировать поток — лечится установкой полного `ffmpeg` и
  **перезапуском OBS**.
- Кодеки зависят от протокола: SRT не принимает AV1, RTMP не принимает MPEG-4.
- Рваный приём гостя лечится буфером: `buffering_mb: 3`, `hw_decode: false`,
  `reconnect_delay_sec: 2–3`.

**Звук**

- EasyEffects своим виртуальным выходом перехватывает всё, что идёт «по устройству
  умолчанию» — указывайте устройство в приложении явно.
- OBS **блокирует захват монитора устройства**, на которое сам выводит мониторинг
  («Prevented feedback-loop»): симптом — в наушниках звук есть, а в миксе программы тишина.
  Обход: выходом по умолчанию сделать виртуальный микс, а звук из него петлёй вернуть в
  наушники.
- Одна и та же гарнитура видна под **двумя именами** (беспроводной донгл и режим зарядки по
  USB). Зашивать точное имя нельзя — ищем по образцу, а выбор владельца храним файлом-строкой.
- Сторож звука должен следить не за модулями, а за **связями петель**: после переподключения
  наушников выход петли может остаться на старом устройстве или играть сразу в два места.
  `pactl` при этом врёт, правду даёт `pw-link`/`pw-dump`.
- Игра на Source-движке (`snd_mute_losefocus = true`) глушит себя, когда окно не в фокусе —
  при стриме это почти всегда. Конвар правится только при закрытой игре.
- Скрипты с `set -e` и `pactl set-default-sink` падают, когда устройства нет (наушники на
  зарядке) — поэтому в выключалке есть живой фолбэк, иначе владелец не может выключить режим.
- Играть файл в эфир надо в тот выход, чей монитор захватывает OBS; проверять «звук дошёл»
  лучше короткой записью и `ffmpeg -af volumedetect`, а не метрами — `GetInputVolumeMeters`
  в части сборок отсутствует.

**Чат**

- Молчание в чате — **не обрыв**: по таймауту шлём `PING` и читаем дальше, иначе соединение
  рвётся каждые пару минут и сообщения теряются.
- Цвет текста задавать явно: в браузерном источнике по умолчанию чёрный и на тёмной сцене
  не виден. Тёмные цвета ников Twitch поднимать по светлоте.
- Эмодзи проксировать через себя и кешировать — до CDN Twitch браузер OBS не дотянется.
- Браузер OBS кеширует страницу: после правок менять адрес источника (`?v=2`) или жать
  «обновить без кэша».
